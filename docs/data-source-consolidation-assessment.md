# 功能与数据源关系及精简评估

核对日期：2026-10-03。评估代码基线：`c3c061b`。状态：保留治理修复前的功能取舍评估；本评估本身没有修改默认来源、功能或取数策略。后续治理已拆同花顺标签、移除中金所伪历史登记并修复数据质量，不代表供应商替代已经实施。当前接口、适配器和接线以 [数据源使用清单](../backend/docs/data-source-usage.md) 为准；下文“当前”均指评估基线。

后续目标“东方财富仅保留热榜，其余能力迁出”的逐项替代接口、候选可用性与热榜隐藏依赖，见 [专项替代评估](eastmoney-hot-only-assessment.md)。该目标尚未实施，不改变本文记录的当前运行事实。

## 1. 结论

连板、题材、概念、财务、资金、热度可以统一归入“股票与市场数据”。这能简化产品和设置中的理解，但同属一个业务组不代表当前一个供应商能提供全部数据。

完整保留现有股票功能、数据内容和口径，现有默认实现仍需要新浪、腾讯、开盘啦和东方财富四家核心来源。只有新浪和腾讯的普通股票 K 等部分能力重叠；四家还有各自独有输入。资讯中的快讯、公告和研报目前主要就是财联社与东方财富两家，东方财富与股票组复用，不增加一家新供应商。

同花顺双榜/标签、中金所期指、社交作者采集、预整理复盘和知识远程更新可按功能列为选配。它们不都属于重复行情或重复快讯。精简有两种结果：取消重复或失效实现可以保持功能；取消独有输入会减少功能/内容覆盖或备用保障，必须分别记录。

## 3. 建议的业务归类与当前来源

### A. 股票与市场数据

| 子功能 | 当前主来源 | 补充/备用 | 是否可以视为重复 |
| --- | --- | --- | --- |
| 股票代码、名称、行业/概念归属 | 东方财富 | 新浪目录仅有已注册沪深名称/报价能力，未作默认备用 | 不等价；新浪不能补全部概念/财务/北交所信息 |
| 报价、五档盘口 | 新浪 | 当前无已接入自动备用 | 无冗余主源 |
| 当日/五日分钟采样、指定日历史分时 | 新浪 | 档案失败可用同源同日近期样本 | 两种覆盖方式，不是两个供应商重复 |
| 普通股票日周月 K | 新浪 | 腾讯 | 有功能重叠，承担备用；来源默认与腾讯 none 的口径不能冒称完全等价 |
| 明确不复权/前复权/后复权 | 腾讯 | 当前无可等价备用 | 腾讯独有默认能力 |
| 年 K、技术指标 | 相应来源价格 | 本地聚合/计算 | 无独立供应商 |
| 主营、财务基本面 | 东方财富 | 当前无已接入备用 | 独有当前输入 |
| 概念和行业成员 | 东财概念/板块；腾讯原生行业成员 | 目录相关候选、题材领涨补充 | 分类/成员身份不同，不能直接当重复列表 |
| 动态短线题材、龙头、题材归因 | 开盘啦 | 行业/概念映射提供其它角度 | 动态短线主题不等于静态概念/行业分类 |
| 涨停、连板、封板信息 | 开盘啦池 | 东财补字段、缺日、缺股票 | 部分重叠，实际为合并；开盘啦已有成交额/首封时间，缺成交价/换手率/行业，旧结构可能缺末封时间；封板事件不能凭价格推造 |
| 炸板、跌停及情绪输入 | 东方财富 | 当前无同等输入 | 情绪计算依赖真实池 |
| 个股/行业/题材资金榜 | 新浪 | 东方财富 | 有重叠但定义不同，总净额和主力净额不等价 |
| 人气/热度 | 同花顺、东财独立榜 | 业务做跨榜比较 | 可选择只留一个平台；会失去另一榜及交叉共识 |
| 竞价参考 | 东方财富 | 同股同日旧点可陈旧返回 | 普通分时不能替代独立竞价参考 |
| 龙虎榜 | 东方财富 | 同花顺平台席位标签 | 原始买卖明细和席位平台分类不是重复字段 |
| 公告、机构/行业研报 | 东方财富 | 当前无已接入备用 | 可归到公司资料/研究证据；它们与快讯不是同类内容 |
| 核心指数、研究基准/日历 | 腾讯指数链路；研究 K 复用原路由 | 同参数旧指数快照可陈旧返回 | 不是独立个股分析供应商；不恢复东财退役指数 |
| 融资余额 | 东方财富 | 当前无备用 | 市场结构输入，不是股票报价重复 |
| 股指期货历史、多空会员/共识 | 东财历史；中金所会员/共识 | 中金所单日持仓降级 | 是选配市场环境功能；单日排名不等于历史曲线 |

公司的公告/财务可在产品上归入股票资料，市场快讯归入资讯；同一东财适配器可以服务两个业务组，不需要创建两份东财客户端或重新计数。

### B. 资讯与内容

| 内容类别 | 当前来源 | 精简建议与影响 |
| --- | --- | --- |
| 市场快讯 | 财联社 | 作为核心资讯保留；删除会失去快讯与对应研究证据 |
| 公告/机构观点 | 东方财富 | 与股票资料复用；公告有可读正文补充（最多8000字），研报为列表字段和链接 |
| 自选作者观点 | 雪球/淘股吧 | 按用户订阅需要选配；删除会失去该平台作者内容，不影响行情或财联社快讯 |
| 微信文章 | 微信链接解析 | 作为按需导入工具；默认无可用自动公众号历史列表订阅 |
| 预整理作者每日复盘 | `official` 远程归档 | 与自己订阅采集存在内容重叠可能，可选择一种作为同一作者/日期的默认获取方式 |
| 历史交易方法 | GitHub资料 + 内置/本地缓存 | 单列知识库；如不需持续更新，可保留内置/缓存而停止远程更新 |

`official` 的发布方案是从微信/雪球/淘股吧具体链接预整理后分发，见 [归档发布方案](daily-review-oss-sync.md)。它不是新增原始新闻供应商。当前没有读取实际远端作者清单或用户内容库，不能据此断言已经重复多少篇文章/作者。

## 4. 当前哪些冗余值得优化

| 现象 | 判断 | 建议 |
| --- | --- | --- |
| 新浪/腾讯/开盘啦/东财一起用于股票功能 | 主要是覆盖差异，不能原样删除任意一家 | 先保留；逐项补齐待替代能力，尤其东财剩余能力 |
| 行业/资金/K有主备 | 属于可选择的可靠性成本，不是多主源乱取 | 按能力明确一主和必要备用；严格复权不换口径 |
| 涨停请求读取两家后合并 | 有请求覆盖重叠，同时承担缺日/缺股/缺字段补充 | 审计字段与历史完整性后，再决定是否只对缺口请求补充；现有缓存命中不等于每次双家网络请求 |
| 两个平台热榜 | 独立内容，功能可精简 | 不需要跨平台比较时选择单榜；相应移除交叉共识展示和提示 |
| 东财内部访问同花顺标签 | 已确认耦合，可优化 | 拆成独立选配标签能力；移除同花顺不能只修改热榜注册 |
| 社交原文采集与预整理归档 | 潜在内容/采集路径重叠 | 按同作者/同日期/同原文设优先路径，不必两条都主动采集 |
| 同内容不同URL、同作者不同平台身份 | 存在内容重复和观点重复计票风险 | 原文规范化、正文哈希和作者关联后，合并证据再做观点统计 |
| 已注册但未默认选用的新浪目录、中金所Trend | 不是默认页面额外主源 | 标注备用候选/探针/兼容用途，不展示成必需主链；去掉登记不等于节省已发生的常规请求 |
| 已退役方法、旧Provider门面、旧注入字段 | 有历史维护成本，但部分仍承担兼容 | 确认消费者后逐步清理；薄委托不等于重复真实请求 |
| 将所有12项放在同一个来源面板里理解 | 分组与状态表达造成混乱 | 展示股票/资讯核心来源，内容采集/知识/衍生品另列按需扩展 |

当前本地文章精确原文 URL 有唯一约束；不同 URL 的同文没有全局正文哈希去重。每日总结按来源和作者ID分组，跨平台同一作者没有统一身份。以上是代码支持范围判断，不是对用户文章库的实际重复率统计。

## 5. 删除来源的具体影响

| 删除来源 | 仍能保留 | 会失去/变化 |
| --- | --- | --- |
| 新浪 | 腾讯日周月 K、东财资金 | 报价/五档、分钟与历史分时；普通K口径变化；没有现成报价替代 |
| 腾讯 | 新浪普通 K、东财行业 | 明确复权、指数/基准备用、原生行业成员、美股ETF |
| 开盘啦 | 东财基础涨停/连板；行业和概念映射 | 原生短线题材、龙头角色、逐股题材证据和保留池主输入 |
| 东方财富 | 新浪价格/资金、腾讯指数/行业、开盘啦已有池（字段/覆盖降级）、同花顺热榜 | 竞价、完整默认目录概念、主营/财务、板块搜索与概念成分、涨停缺日/缺股及成交价/换手/行业等补充、炸板/跌停、龙虎榜/融资、公告/研报、东财热榜及双榜共识、期指历史；仅留东财热榜的目标另见专项评估 |
| 同花顺 | 东财单榜、龙虎榜原始明细 | 同花顺热榜、跨榜共识、平台席位标签；还要停止东财内部标签请求 |
| 中金所 | 东财历史期指 | 会员明细、四品种共识、主历史失败后的单日降级 |
| 财联社 | 股票行情和公司公告/研报 | 当前市场快讯及研究快讯证据 |

## 6. 三种精简目标

| 方案 | 核心来源/范围 | 结果 |
| --- | --- | --- |
| 保留全部现有功能 | 当前核心与扩展都保留 | 优先统一分类、默认选源、内容去重和内部耦合；不能承诺无损减少供应商 |
| 股票核心优先 | 股票保留新浪、腾讯、开盘啦、东财；快讯财联社；同花顺/中金所/文章平台/知识更新按需扩展 | 核心默认外部依赖目标为5家；这仅是建议，尚无统一扩展启停界面。核心股票+公司资讯为4家，快讯额外1家 |
| 全部股票只留1–2家 | 现有来源组合没有完整覆盖 | 需要新的可靠适配实现和覆盖验收，或者明确放弃独有功能；本轮未评估新供应商，也不把删功能称为完成替代 |

更符合当前目标的是第二种作为规划基线：保留核心股票功能，降低默认启用范围，选配作者采集、双热榜和期指。是否实际关闭这些功能，需在完整功能关系可理解后由用户选择；本轮不执行删除。

## 7. 建议实施顺序与验收

1. 先确定功能范围。股票数据覆盖价格、资料、题材/连板、交易行为和市场背景；资讯覆盖快讯及公司研究；作者内容/知识更新/期指明确选配。分类调整本身不换来源。
2. 完成当前边界收口。拆同花顺标签，校正替换后的来源身份，统一默认知识装配；让可选功能显式启用，未启用不请求。
3. 按作者与原文解决内容重复。保留实际出处；归档与原平台不重复计为独立观点，旧记录不删除。
4. 根据需求精简双热榜、期指和内容渠道。列出关闭后的页面/研究证据变化；去掉来源同时调整能力路由与内部补充调用。
5. 继续按 [东财替换计划](source-replacement-rollout.md) 逐项替代剩余竞价、资料、池、公告/研报等。退役股票价格和指数不恢复，不能为数量目标删除功能或伪造数据。
6. 每项能力验收覆盖、日期、字段、单位、复权/成员/排名口径和故障降级，并检查HTTP页面、研究、持仓、复盘和后台任务共用链路。代码通过测试不等于新上游已证明覆盖。

本轮仅进行源码/文档评估，未修改逻辑、删除来源、读取本机凭据或测试公网。也未统计实际功能使用频率、网络请求耗时或作者正文重复率；后续取舍以明确需求与必要样本验证为依据。
