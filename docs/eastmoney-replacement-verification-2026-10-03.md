# 东方财富现役能力与替代验证汇总

核对时间：2026-10-03 20:25起，Asia/Shanghai；当前适配器样本采集约20:29–20:30，候选官网/API随后低频核对。代码基线：`e8825e58f8c1f97fc6a5753cad8e57241c6a571e`。

范围：本项目实际使用的东方财富能力，不是东方财富网站所有产品；替代源仅限当前已接入的新浪、腾讯、开盘啦/短线侠、同花顺、中金所、财联社。没有新增供应商、改默认路由、关闭功能、读取个人配置/登录态或提交推送。本文是新的验证记录，不改写此前评估的历史证据。

## 1. 总结

**现有其它来源不能现在就无损接管东方财富全部剩余能力。** 架构允许替换，但适配器、字段语义和完整覆盖尚未齐备。

- 已迁出且不应恢复：股票普通K、明确复权、指数快照/历史；报价与分时本来走新浪。同花顺龙虎榜标签也已经独立，不再由东财明细隐式访问。
- 已实现基础功能可继续：腾讯行业动量/原生成员、新浪三类资金榜、同花顺热榜。取消东财仍会失去备用保障、独立榜单或部分字段，不能写成同口径无损替代。
- 已实现但仅部分：新浪沪深名称目录、开盘啦当前涨停/本地历史池、中金所指定合约/日期会员排名。
- 新公共候选有实证：新浪公司资料、结构化财务、公告列表/正文、公司/行业研报；同花顺概念目录/成员页面。它们属于已有供应商的新能力，当前尚无对应已接入适配器。
- 主要阻断：09:15–09:25竞价指示价轨迹、完整最终炸板/跌停池、完整可回补涨停历史、完整概念成员/反向归属、全市场融资、龙虎榜精确日期买卖明细、期指主力目录/价格/基差历史。

不能把“官网有数据”“样本HTTP200”“实现了标准适配器”“消费者已无东财请求”“长期可靠”混为同一个完成状态。

## 2. 验证方法与边界

1. **源码核对**：默认登记、显式Routes、实际HTTP/研究/题材/热榜/情绪消费者，确认隐式依赖。
2. **当前适配器实网样本**：全新客户端，不读应用缓存或用户数据库；16项能力采样、23次实际HTTP尝试，统一串行访问且相邻上游尝试至少1.2秒，最多40次预算。包括失败和供应商内部有限重试，进程退出0只表示采样完成，不代表全部来源健康。
3. **候选官网/API**：匿名低频读取真实字段、日期/正文，未执行反爬绕过、登录、SDK授权或服务器扫描。
4. 10月3日是周六/国庆休市；本次池及会员数据日为9月30日，网页财务报告期为6月30日。资金榜缺原始业务时间，不能仅因抓取时间20点就称盘中实时或准确指定9月30日。
5. 没有交易时段持续刷新、全股票/板块/历史分页、全量市场覆盖、长期成功率或SLA验收；没有宣布新适配器已投产。

## 6. 删除东财前必须处理的隐藏依赖

1. **热榜补名**：[stock_hot.go](../backend/internal/httpapi/stock_hot.go#L105-L124)无论两榜还是THS单榜，默认仍读东财Directory；THS原生有名称并不自动停止此目录请求。
2. **题材/行业候选**：腾讯原生成员成功前仍并发执行mapper候选路径；mapper读取默认东财Boards和Directory。[radar.go](../backend/internal/sector/radar.go#L162-L197)、[server.go](../backend/internal/httpapi/server.go#L244-L250)。
3. **涨停合并**：开盘啦不是仅失败才读东财；常规服务读取东财历史并补股/补字段。[limit_up.go](../backend/internal/datasource/service/limit_up.go#L134-L178)。
4. **研究/情绪**：研究并发读取目录、主营/财务、公告/研报及40日涨停；情绪还用真实炸板/跌停和目录。页面价格看起来已经非东财，不等于AI证据链无东财。
5. **期指另包**：东方财富历史在futuresposition而不只在providers/eastmoney；不能删一个目录即算移除。
6. **探针与链接**：ProbeDirectory独立读东财；旧原文链接和历史来源应继续可解释，但不能触发新的东财取数。判定替代完成应以拦截新网络请求为准，不要求抹掉历史证据。
7. **默认路由/空能力**：Registry可移除，但Routes仍引用会启动报错；清空路由只是禁用，不算功能替代。

## 7. 当前基线自身的限制

不应先把东财当前响应当成全量真值再强迫其它源完全复刻：
- Boards主列表为行业、BoardStocks当前首分页，不能宣称所有概念/成员全集。
- 官方样本资金回退只有主力净额，缺字段不等于0。
- 龙虎榜fetchBillboardDate过滤只有TRADE_DATE>=请求日、没有上界，随后输出日期使用请求日；历史日期可能混入后续日，此契约应先修正再做精确逐日对照。[源码](../backend/internal/providers/eastmoney/market_overview.go#L559-L568)。本轮只记录问题，未改生产逻辑。
- 侧池炸板/跌停尚没有涨停History同样严格的null/presence完整性验证；空响应不能不经检查当真实0。
- 资金榜原始时间、热榜平台时间、公司资料更新时间等仍有未知。

## 8. 推荐迁移顺序与验收

1. **资料/财务**：优先新浪结构化财务和公司资料，先做离线字段映射、沪深京/金融业/缺失/累计单季/发布日期样本，不改评分口径掩盖差异。
2. **公告/研报**：接新浪列表+正文；先检索、分页、公司/行业/日期、内容范围与评级/预测结构化验收。财联社继续只作快讯，不冒公告研报备用。
3. **目录拆分**：薄代码名称目录与行业/概念会员索引分开。新浪先服务沪深名称；THS概念完整分页和反向映射验收后迁出东财分类。
4. **行业/资金/热榜**：主链已非东财，减少东财备用前明确缺字段/分类/独立榜单变化。单榜精简必须用户接受失去双榜，不能称无损。
5. **涨停/期指历史建设**：扩持久保留/回补与日期覆盖；中金所逐日同合约排名独立落库，价格/结算/主力换月另验。不要用缺价格的持仓曲线伪基差。
6. **最后处理硬阻断**：竞价轨迹、真实最终炸板/跌停池、全市场融资、原始龙虎榜。没有通过的等价公共输入就暂留东财，并标不可用/部分覆盖，不通过删功能实现“替换完成”。

验收底线：每项独立实现与显式注册/路由；source、单位、业务时间/发布日期、字段存在性、分类身份、total/returned/complete、请求/覆盖/缺日、内容范围明确；冷缓存与故障路径不回东财；HTTP/研究/持仓/复盘/调度/探针全消费者拦截证明新东财取数为0；保留旧报告与数据库，不重标或删除历史。

**结论：本轮找到了不新增供应商即可推进多项替代的可靠样本方向，尤其新浪结构化财务和最新研报；但现有已实现适配器仍不足以无损全替换东财。应按能力迁移，不能一次删掉整个来源。**
