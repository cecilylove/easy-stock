## 已确认问题与改造验收条件

### 1. 集合竞价：确实复现上游不稳定

- 17:26 首轮：`600519.SH`、`000001.SZ` 的生产适配器均从 `push2.eastmoney.com/api/qt/stock/trends2/get` 返回 HTTP 200，每只解析出 9/30 09:15–09:25 的 11 个参考点。增加浏览器 UA/Referer 的对照请求也成功。
- 17:32 第二轮：同样两个代码，主节点及 `82.push2`、`90.push2` 全部 EOF；浏览器请求头对照也失败。镜像仍是同一供应商，不能认定为独立备源。
- 业务 `/api/v1/quotes/auction?symbol=600519.SH` 与 `detail=1` 都返回 502、`status=unavailable`、空 points。页面明确显示不可用并提供重试，没有把 9/30 连续交易数据拼到 10/3 竞价里。
- 因此无法判定为“永久用不了”，但足以否定“稳定可用”。目前没有已验证的独立、同语义竞价备用源；报价五档、成交分钟线不能直接替代竞价参考轨迹。

另有一个独立的提示问题：`backend/internal/httpapi/auction.go` 的 detail 分支把“成功返回历史日、没有当日竞价点”当成错误，最后也输出“上游无响应”；普通分支则返回 historical。`TestAuctionDetailHistoricalIsNotSourceFailure` 的模拟历史输入及代码检查证明这一差异。**本轮实际 502 同时有真实 EOF 证据，不能全部归因于提示问题。**

验收条件：区分网络失败、字段不完整、非交易日/只有历史日；历史日不冒充当日竞价；各竞价节点的失败应能按能力追踪。更换竞价源前需确认相同字段语义，不能先删功能或用成交价伪造竞价。

### 2. 融资余额：部分市场被显示成全市场（优先修复）

原始 `RPTA_WEB_RZRQ_LSSH` 数据：9/30 只有 SCDM=007（沪市）；9/29、9/28 有 001（深市）、002（北交所）、007（沪市）。当前 `MarketMarginSeries` 虽请求市场字段，但解析结构没有保留市场身份，直接按日期累加，随后无条件计算跨日变化。

| 日期 | 实际覆盖 | 当前接口两融余额（元） |
| --- | --- | ---: |
| 2026-09-29 | 沪深京 | 2,608,990,447,105 |
| 2026-09-30 | 仅沪市 | 1,315,413,245,429 |

接口生成 `margin_balance_change=-1293577201676`。页面仍声明“沪市、深市、北交所合并口径”，显示 **−12,935.77 亿**；这属于覆盖不完整的比较，不能解释为全市场真实下降。前端融资 AI 上下文也直接采用这些金额，存在继续传入分析的风险；本轮未调用 AI。

位置：`backend/internal/providers/eastmoney/market_overview.go` 的 `MarketMarginSeries`；`frontend/src/components/market/MarketDataViews.tsx` 的融资视图；`frontend/src/lib/market-overview.ts` 的融资上下文。

验收条件：保留市场身份并检查完整性；缺市场时跳过该日或明确标记部分覆盖；不同覆盖集合不计算日变化；未知不能当零；页面及分析上下文遵守完整性标记。回归必须包含“最新仅沪市、前日沪深京”样本。

### 3. 龙虎榜：原生席位字段被当数量（优先修复）

原始 BUY_SEAT/SELL_SEAT 样本有 11111、33133、13333、11331、33313 等。`MarketBillboard` 将它们直接转为 int；`LimitUpWorkspace.tsx` 无条件显示为席数。

- 业务列表 API 已返回 `buy_seats=11111`、`sell_seats=11111`。
- 连板页新华传媒 9/30 弹窗实测显示“买方 11111席 / 卖方 11111席”，同一弹窗的实际明细各 5 行。
- 行情总览的龙虎榜主列表没有显示这一错误数量；买卖五席展开也正常。影响点是列表契约以及消费该契约的连板弹窗，不能把整个龙虎榜功能统称为不可用。

供应商原生值的具体编码含义本轮未获可靠说明，不能凭字符串长度猜成 5。验收条件：不再把未确认的原生值映射为数量；未知数量隐藏或明确表示；详情加载后可按真实返回的买卖数组长度显示。回归需覆盖 11111/33133 等真实原生样本，以及详情不足 5 席的情况。

### 4. 题材资金回退：只恢复部分字段

东方财富 push2 题材资金两次 EOF；现有 `data.eastmoney.com/dataapi/bkzj/getbkzj` 回退正常返回，但仅提供主力净流入，没有分单净额和相应比例。不能把回退 HTTP 200 当成全部字段恢复。

验收条件：保留降级来源及字段可用性；缺失指标显示未知，排序和分析不把未知当零；主接口与回退分别记录能力观测。

### 5. 代表接口检测覆盖不了上述问题

`POST /api/v1/sources/check` 的七个代表接口本次全部返回 available，包含东财目录检测。这与竞价失败并不矛盾：目录正常不能证明竞价正常；融资与龙虎榜即使 HTTP 200，也有语义错误。

验收条件：保留“手动代表探针”与“业务能力观测”的区别；竞价应有独立结果；融资市场覆盖与龙虎榜字段语义需要契约检查。来源总状态正常不能被描述为所有功能通过。
