# 东方财富仅保留热榜：替代能力与依赖评估

核对日期：2026-10-03。评估代码基线：`c3c061b`。状态：保留治理修复前的替代评估，尚未实施“仅留热榜”的供应商替换。后续已将同花顺标签拆成独立能力、规范研报/主营来源及移除中金所伪历史登记；下文相关历史依赖按基线保留，当前接线见 [数据源使用清单](../backend/docs/data-source-usage.md)。范围是现有供应商，不新增供应商，不以减少功能作为完成替换。

本文将用户的“只留热榜”解释为：东方财富仅保留 `HotRank`，其它东财能力迁出；并不同时决定删除同花顺热榜。当前完整接线见 [数据源使用清单](../backend/docs/data-source-usage.md)，此前精简评估见 [功能与来源关系](data-source-consolidation-assessment.md)。

## 1. 评估结论

目标在架构上可行，东财热榜协议实现已经独立；但现有其它适配器尚不足以无损替代东财全部剩余能力，当前不能直接移除。

- 已有主链可继续：腾讯行业强度、新浪资金榜；移除东财备用仍会改变字段覆盖和失败保障。
- 已有部分替代：新浪沪深名称目录、腾讯原生行业成员、开盘啦涨停池、中金所按历史日期取会员数据；它们都存在范围、字段或历史建设缺口。
- 已发现供应商官网数据/平台接口候选，尚未接入：概念、主营、财务、融资、龙虎榜、公告、研报。
- 仍缺可靠等价输入：09:15–09:25竞价参考轨迹、完整最终炸板池、跌停池，以及上述部分替代的缺口。

“官网有数据”“平台 API 有方法”“本机可稳定调用”“适配器已满足业务契约”是不同状态。本次确认前两类候选，不把它们写成已经完成后两类验收。所有未完成项都不能靠修改注册表补齐。

## 3. 对候选接口的可用性限制

[同花顺官方平台 API 文档](https://quant.10jqka.com.cn/view/help/4)明确包含 `get_concept_stocks`、`get_concept_relate`、`concept_classification` 查询及 `get_fundamentals`。这能证明供应商有相应平台能力，但不是已经证实可供本项目 Go 后端匿名 HTTP 调用的接口。

[本地 SDK 说明](https://quant.10jqka.com.cn/view/help/3)当前要求机构及团队条件，并走申请审核。因此不能把这些平台方法作为本个人项目现成可用、无需授权的默认替代。应先验证公共页面/实际请求是否能稳定满足契约，再决定接入；此轮未申请权限、未引入账户或付费依赖。

官网页面样本也不证明全量覆盖或长期稳定。替代验收至少区分沪深京、主板/创业板/科创板、ST/停牌等样本；检查分页、交易日、真实缺失、反爬/限流、单位和来源时间。公告、财务、研报分别验收，不因一个页面可读就将整家标为全部通过。

## 4. 开盘啦和中金所的具体边界

开盘啦池已经解析名称、涨幅、成交额、流通市值、连板数、首封时间、开板次数、N天M板和池内概念；较长返回结构还解析末封时间。不能泛称它缺成交额或首封时间。当前未解析成交价、换手率、行业；旧结构可能没有末封时间。

`FetchLimitUpPool` 没有日期参数。池日期取 `Last-Modified`，缺失时用获取日期；本地按交易日留一条、保留最近16条，无法回补启动前或漏采日期。删东财后必须明确真实历史覆盖，不能把缺日当空池，也不能从普通报价推造封板事件。

中金所会员接口可按历史日期读取，并非只能读最近日；但前20会员数据、全合约共识、单主力合约历史是不同口径。构建历史需确定固定合约或明确的主力换月规则，逐日验证原生日期/合约/排名完整性，保存缺日与失败。会员持仓无法补结算价、指数收盘、基差；官网日行情是价格候选，尚未完成本项目接入与对齐验收。

## 5. 热榜能否单独保留

可以。`providers/hotstock` 的 `NewEastMoneyRankClient` 与重型 `providers/eastmoney` 没有包依赖。构造时不取数；`HotRank` 只请求：

```text
POST https://emappdata.eastmoney.com/stockrank/getAllCurrentList
```

当前代码不需要账号、Cookie、Token，也不调用主营、财务、概念、报价或期指。返回主要是股票符号 `sc` 和排名 `rk`，没有名称。代码中的这一事实不保证上游未来始终可用。

当前仍有以下外围依赖，需要在实施中处理：

1. **名称补充**：`httpapi/stock_hot.go` 同时等待热榜与默认东财目录。目录失败不阻断排名，但东财独有股票可能只显示代码。热榜只需要代码/名称，不需要财务/概念；可改非东财名称目录或独立报价补名，并避免完整目录慢请求拖住热榜。新浪现有目录可覆盖沪深，其它证券范围还需验收。
2. **代表检测**：设置中东财检测仍请求新客户端股票目录。需改为独立新鲜热榜探针及 `ProbeScope`；东财热榜不返回名称，探针不能套用名称非空校验，也不能通过同花顺或缓存替东财报成功。
3. **注册/路由**：保留稳定 `eastmoney` ID，仅注册 `HotRank` 并收窄描述。移除其它东财能力绑定/路由，配置校验继续拒绝悬空能力。保留 ID 方便历史报告、热榜排名和来源观测兼容。
4. **期指另包**：`providers/futuresposition.NewHistoryClient` 仍请求 `datacenter-web.eastmoney.com`；删除 `providers/eastmoney` 不会删除它，必须同时迁出历史路由/实现。中金所 exchange-only 路径本身不请求东财。
5. **点击后的完整业务**：热榜传完整证券代码进入研究，不需要概念目录才能解析代码；但研究会调用主营、财务、公告/研报、概念与池等能力。只有这些全部迁出，才达到完整操作路径仅访问东财热榜。
6. **来源身份与事实判断**：`sector/mapper.go`、`stockanalysis/{engine,new_listing,theme_attribution,theme_ai}.go` 有东财固定来源/标题及 `f10-business` 识别；普通个股和新股分支都硬编码研报来源为 `eastmoney:report`。新证据应携带实际来源，并把“主营事实”判断从供应商字符串解耦；否则替换接口后仍可能误标或漏算。历史报告保持原始东财来源。
7. **前端链接与文字**：报价侧栏原始行情外链、龙虎榜说明引用仍指向东财；它们不是后台取数依赖，但“仅留热榜”产品清理应改新采集结果的直达链接。历史证据原链接保留。双榜维持时无需删共识；若另行决定只留东财单榜，再调整双榜提示和共识解释。

| --- | --- | --- |

最终检查覆盖：个股详情（含竞价开关）、名称搜索、热榜加载/刷新/点击研究、个股研究/持仓巡检（包含新股分析分支）、趋势题材/成员、连板与历史对比/情绪、总览全部模块、复盘证据、来源手动检测，以及缓存失效/备用失败/重启后的请求。旧缓存可读不算本次迁移成功；应在不读取个人数据的隔离环境验证冷缓存和失败路径。

新增适配器仍需要实现契约、注册能力、配置路由和验证消费者。只给统一结构赋值不足以验证字段语义、证券/分类身份、历史覆盖和缺失处理。用请求拦截回归证明非热榜东财访问为零，同时防止未注册遗留门面绕回东财；不要仅依据设置目录删掉能力标签判定完成。
